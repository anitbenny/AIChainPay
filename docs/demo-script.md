# Demonstration and evidence checklist

Use only Sepolia test ETH and addresses you control or have permission to pay. Record the date, actual client/version, chain ID, deployed vault address/block/transaction hash and source of each observation. Do not record or publish keys, seed phrases, OAuth tokens, session cookies, raw signed transactions or private RPC credentials. The present repository has local-chain evidence only; fill live evidence in [implementation status](../IMPLEMENTATION_STATUS.md) after it actually happens.

1. **Build and contract evidence.** Run `npm.cmd ci`, `npm.cmd run build`, `npm.cmd test`. Show the Solidity tests, backend auth checks and source-controlled ABI. Explain that owner credit is on-chain and the agent cannot spend ordinary MetaMask ETH.
2. **Local setup evidence.** Run `npm.cmd run chain`, `npm.cmd run deploy:local`, configure ignored `connector/.env` for local chain 31337, then `npm.cmd run dev:connector`. Open `http://localhost:3000`. The screenshot in [screenshots](./screenshots/) is a real local browser/local-chain run with an injected test provider, not a mockup or real MetaMask.
3. **Sepolia deployment.** Set separate deployment-only credentials locally, run `npm.cmd run deploy:sepolia`, and copy actual manifest fields to backend/frontend configuration. Verify chain ID, contract code hash and block explorer. Do not claim deployment if the transaction was not mined.
4. **Owner MetaMask actions.** On Sepolia, connect and sign the expiring SIWE message; explain it authorizes login only. Deposit a small amount (vault credit; owner pays gas). Grant the dedicated agent a smaller total allowance and per-payment cap, short expiry and preferably an allowlist (on-chain authorization; owner pays gas). Note the exact transaction hashes and balances after receipts. Neither action authorizes spending from the ordinary wallet after deposit.
5. **Real chat gate.** Add the HTTPS MCP endpoint in a capable ChatGPT account. Complete OAuth and verify wallet-linked read tools against Sepolia. Run the harmless write probe and inspect native approval. Prepare a payment and inspect whether the execution approval screen binds the **full** immutable transfer details. If it does not, stop and leave execution disabled. Record the actual client/version and result, not an inference from docs.
6. **Tiny payment only after approval feasibility passes.** Deliberately accept one in-chat write for a known recipient and small test amount. It authorizes the backend agent to broadcast that exact stored vault transfer; it is not an owner MetaMask transaction. Wait for actual receipt/required confirmations, compare recipient balance delta, contract event, owner vault debit and grant allowance decrease. Save explorer hash. The chat may need a later `get_request_status` request.
7. **Negative and revocation evidence.** Decline another proposed execution and show zero new transaction attempts. Try an over-cap amount and show refusal. Revoke the agent in MetaMask: that transaction invalidates future delegated payments once mined, but does not undo earlier ones and can race with a pending agent transaction. Show subsequent execution blocked. Disconnecting OAuth/browser separately does not revoke the grant.

The current local integration scripts (`npm.cmd run test:local-mcp`, `npm.cmd run test:local-ui`, `npm.cmd run test:local-execution`) can support steps 1–2, but **cannot replace** steps 3–7.
