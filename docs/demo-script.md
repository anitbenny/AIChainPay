# Demonstration and evidence checklist

Use only Sepolia test ETH and addresses you control or have permission to pay. Record the date, actual client/version, chain ID, deployed vault address/block/transaction hash and source of each observation. Do not record or publish keys, seed phrases, OAuth tokens, session cookies, raw signed transactions or private RPC credentials. Sepolia deployment, owner login/deposit/grant, ChatGPT reads/preparation, exact live-card approval and [the confirmed 0.0001 ETH payment](https://sepolia.etherscan.io/tx/0x2bfe8bfc442c084cc012fed2b345044819bad1a11dfef682fea7a7e0cbff01cf) are observed. An authenticated over-cap 0.002 ETH preparation was refused without a transaction. Do not repeat the successful payment. A later [revoke](https://sepolia.etherscan.io/tx/0x1e8d94f28b434eb393d8e16e830bdd52cb28b7ccc6ceeddd9fcbf7d72) and [regrant](https://sepolia.etherscan.io/tx/0x5759f2a59d21ad4e1842cb3c07eff8a1e205498d7ebd08bc8c908612e93e4526) also succeeded; current grant values must be read afresh. See [implementation status](../IMPLEMENTATION_STATUS.md).

1. **Build and contract evidence.** Run `npm.cmd ci`, `npm.cmd run build`, `npm.cmd test`. Show the Solidity tests, backend auth checks and source-controlled ABI. Explain that owner credit is on-chain and the agent cannot spend ordinary MetaMask ETH.
2. **Local setup evidence.** Local tests use a separate chain 31337. Do not overwrite the current Sepolia environment or redeploy its contract. `npm.cmd run test:local-card-execution` exercises the card decision/signer/contract pipeline with synthetic decisions and real local transactions. Screenshots are explicitly labelled by evidence type.
3. **Sepolia deployment.** The existing manifest records the deployed vault. Run `npm.cmd run verify:sepolia` read-only; do not redeploy for the demo. Keep execution disabled with `npm.cmd run start:sepolia` until the real card gate passes.
4. **Owner MetaMask actions.** On Sepolia, connect and sign the expiring SIWE message; explain it authorizes login only. Deposit a small amount (vault credit; owner pays gas). Grant the dedicated agent a smaller total allowance and per-payment cap, short expiry and preferably an allowlist (on-chain authorization; owner pays gas). Note the exact transaction hashes and balances after receipts. Neither action authorizes spending from the ordinary wallet after deposit.
5. **Real chat gate.** Refresh the existing plugin's tool metadata. Prepare a fresh payment and invoke `show_payment_confirmation`. The interactive card must render inside ChatGPT with the full exact intent and verification-only label. Test its Confirm and Reject on separate requests while execution stays disabled; verify the recorded modes and no transaction attempts. If unsupported, stop live activation. Do not repeat the old generic/native probe or equate its approval with payment confirmation.
6. **Tiny payment only after approval feasibility passes.** Fund the separate agent's gas with an explicitly explained owner transaction. Record real card verification and enable only the app adapter using the gated live startup. Prepare a NEW intent and live card, then explicitly click Confirm for a small test amount. It authorizes that exact vault transfer, not ordinary MetaMask spending. Verify receipt/confirmations, recipient balance delta, contract event, owner debit and allowance decrease. Ask `get_request_status` for the final result. Verification-mode clicks do not carry over.
7. **Negative and revocation evidence.** Verification-mode card rejection was recorded with no transaction. The over-cap preparation refusal is recorded above. The historical revoke receipt and a read-only `PermissionInactive` simulation during the revoked interval are evidence; a later regrant restored spending permission. If demonstrating another revoke, explain before asking for a new MetaMask signature. It does not undo earlier payments and can race with a pending agent transaction. Disconnecting OAuth/browser separately does not revoke the grant.
8. **Post-demo shutdown.** After the revoke receipt and inactive-grant read, optionally withdraw remaining vault credit with a separate owner MetaMask transaction. Disconnect/remove the AIChainPay custom MCP connection in ChatGPT. Stop the backend and HTTPS tunnel/host last. Preserve the database and agent key until pending signed transactions are resolved. See the [shutdown sequence](./client-integration.md#post-demo-shutdown).

The current local integration scripts (`npm.cmd run test:local-mcp`, `npm.cmd run test:local-ui`, `npm.cmd run test:local-execution`) can support steps 1–2, but **cannot replace** steps 3–7.
