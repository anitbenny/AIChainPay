# Architecture decisions (2026-10-18)

1. **Two network modes, no silent fallback.** Production accepts Sepolia chain ID 11155111 only; chain 31337 requires explicit `ALLOW_LOCAL_CHAIN=1` and is for development tests. The connector checks RPC chain ID, nonempty bytecode, vault ABI identity and the exact deployment code hash on Sepolia before serving. MCP tools cannot choose RPC, chain or contract.
2. **Vault delegation.** MetaMask retains the owner key and signs setup actions. A separate backend agent pays its own gas and may spend only credited vault ETH under the contract's bounded, expiring, revocable grant. A new grant replaces the old one and increments its epoch. Owner-as-recipient is rejected to avoid duplicate participant indexing. No upgradeable proxy, privileged drain or ordinary-wallet spending is implemented.
3. **Compatible pinned versions.** Node 22.22.2 was available and satisfies [Hardhat 3's Node 22.13+ requirement](https://hardhat.org/docs/getting-started). Current registry versions were queried and pinned: Hardhat 3.20.0 with `@nomicfoundation/hardhat-toolbox-mocha-ethers` 4.0.0, Solidity 0.8.28, ethers 6.17.0, OpenZeppelin Contracts 5.6.1, TypeScript 5.9.3, MCP SDK 1.32.1, `oidc-provider` 9.12.2, `siwe` 3.0.0, `better-sqlite3` 12.4.1, Express 5.3.0, React 19.3.1, Vite 8.3.4, plugin-react 6.1.2, Tailwind 4.3.3 and zod 3.25.76. SQLite 13.0.3 failed a clean install on this Windows host because its native build required a missing C++ toolset; 12.4.1 installed and loaded after clean `npm.cmd ci`. Zod v3 is used with the published MCP SDK v1 API. Exact direct/transitive resolution is in [package-lock.json](../package-lock.json). Sources: [Hardhat ethers tests](https://hardhat.org/docs/guides/testing/using-ethers), [Hardhat deployment](https://hardhat.org/docs/guides/deployment/using-scripts), [ethers v6](https://docs.ethers.org/v6/), [OpenZeppelin 5.x](https://docs.openzeppelin.com/contracts/5.x/), [official MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server).
4. **ChatGPT first, evidence-gated execution.** [OpenAI's custom-MCP guide](https://developers.openai.com/plugins/build/mcp-server), [auth guide](https://developers.openai.com/plugins/build/auth) and [connection guide](https://developers.openai.com/plugins/deploy/connect-chatgpt) support the selected remote MCP/OAuth path. The live account and approval UI have not been tested. MCP [elicitation rules](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation) exclude form-mode financial authorization, so the preferred in-band form approach is not used. The candidate adapter is ChatGPT's native per-write approval; the server trusts the client and receives no click proof. It is disabled by default and may be enabled only after an actual full-detail approval test. Claude is unverified.
5. **Wallet-linked OAuth.** A one-use [SIWE](https://eips.ethereum.org/EIPS/eip-4361) challenge verifies an EOA. `oidc-provider` handles OAuth authorization code/PKCE, token persistence, discovery and resource audience; the app handles wallet login and scoped consent. Production client registration targets ChatGPT's Client ID Metadata Document route; a fixed local client is only for protocol tests. OAuth disconnection never revokes Solidity permission.
6. **One-origin single-instance deployment.** The connector serves built frontend, browser API, OAuth and MCP under one HTTPS origin; Vite uses a development proxy. SQLite uses WAL, migrations and persistent disk for one backend writer. An in-process signer queue plus database CAS, unique nonce and signed-before-broadcast persistence prevent the tested duplicate/race cases. Multiple backend writers or a shared agent used elsewhere require a redesigned distributed nonce coordinator, not just another server replica.
7. **Event and receipt truth.** The indexer scans `PaymentExecuted` from the actual deployment block in bounded batches, overlaps recent blocks for shallow reorgs, keys cursors by chain/contract, and reports incomplete catch-up. Request state and payment events are distinct. Receipt reconciliation checks actual signer, chain, target, nonce and matching event; it never invents a successful transfer or equates `submitted` with `confirmed`.
8. **Secrets and deployment.** Separate root deployment-only `.env` and connector `.env` keep deployer and agent identities apart; Vite variables are public. OAuth signing JWK, SQLite and all secret-bearing files are Git-ignored. The agent signed payload is encrypted before SQLite persistence. The local manifest/screenshot are explicitly chain 31337 evidence; no Sepolia deployment or GitHub remote is represented as existing.
